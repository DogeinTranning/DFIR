# Email Forensics

## Key Questions in Email Examinations

1. Who sent the email?
  - Emails aren't autonomously generated by computers.
  - Investigators try to identify the originator using:
    - Email addresses
    - IP addresses
    - Metadata like signature blocks or references
2. When was it sent?
  - Emails include timestamps.
  - Server-side timestamps (often multiple) are more reliable and harder to fake.
3. Is it authentic?
  - Headers can confirm authenticity through:
    - Embedded timestamps
    - Technologies like SPF, DKIM, ARC
4. Where was it sent from?
  - Original IP addresses can help locate the sender.
  - Geolocation tools and ISP tracing may narrow down the origin.
5. Is there relevant content?
  - Content is crucial for the investigation.
  - Beyond messages, investigators also examine:
    - Contacts
    - Calendar appointments
    - Task lists
## Three basic components of email analysis

1. Email Headers
  - Rich in metadata: origin IP, sender address, mail servers, timestamps.
  - Often hidden by default in clients; must be manually revealed.
  - Tools exist for header parsing and analysis.
2. Email Body
  - Easier to analyze than headers.
  - Manual review is often needed, especially for foreign languages or encoded data.
  - Keyword search and deduplication (e.g., searching all messages for fraud-related terms) is key.
  - Important: email messages can be stored as binary, so string searches alone may miss hits. Native email forensic tools are recommended.
3. Attachments
  - Estimated 80% of email data resides in attachments.
  - Common malware vector: attachments should be scanned for viruses.
  - Often stored in MIME/base64 format — appears garbled until decoded.
  - Specialized tools or email clients are needed to view them properly.
## Email Header and Transmission

- Email headers act as the metadata envelope, logging:
  - Sender and recipient.
  - Timestamps (send and receive).
  - Routing path across MTAs (Mail Transfer Agents).
- Sending process:
  - Email is created in a client (e.g., Outlook or Yahoo!).
  - Sent to an originating SMTP server (MTA).
  - Routed across the internet through multiple MTAs.
  - Delivered to the recipient's MTA, then their message store (e.g., POP3/IMAP).
- Key Metadata Fields in Headers
  - Message-ID: Unique ID assigned by the originating mail server.
  - Received: Tracks each mail server hop (includes IP, hostname, timestamp).
  - X-Originating-IP / X-Forwarded-For:
    - Reveals IP of the sender's device or proxy chain (if not spoofed).
    - Sometimes suppressed for privacy, but useful when present.
  - X-Mailer: Indicates the client used (e.g., iPhone Mail, Outlook).
## Email Authentication and Verification

- SPF (Sender Policy Framework):
  - Found in headers as Received-SPF.
  - Validates whether a mail server is allowed to send emails on behalf of a domain.
  - Helps prevent spoofing by verifying the sending IP address.
- DKIM (DomainKeys Identified Mail):
  - Uses digital signatures to verify that the message content has not been altered.
  - Adds integrity to both the content and the sending domain.
  - Validation only works if the DKIM keys are still available and have not rotated.
- ARC (Authenticated Received Chain):
  - Designed to preserve original authentication results across intermediaries like forwarders.
  - Uses headers such as ARC-Authentication-Results and ARC-Message-Signature.
  - Especially useful in complex mail flows involving mailing lists or forwarders.
- DMARC (Domain-based Message Authentication, Reporting, and Conformance):
  - Sets policies on what to do when SPF and/or DKIM fail.
  - Example policy line: dmarc=pass (p=REJECT dis=NONE) header.from=outlook.com
- Validation Tools:
  - MxToolbox: Checks SPF records.
  - dkimpy (Python): Validates DKIM/ARC signatures.
  - Metaspike FEC: Automates forensic email analysis.
- Limitations:
  - DKIM/ARC keys can rotate or expire.
  - Some mail clients may strip or alter original header data during export.
  - Always collect emails in their original MIME formats (e.g., EML, EMLX, MBOX) for maximum forensic value.
## Email Threading

- Message-ID:
  - Every email message has a unique identifier assigned to it.
  - Essential for tracking and correlating emails across systems and threads.
- References:
  - Contains a list of message-IDs from prior emails in the conversation thread.
  - Typically appended with each reply.
  - Most complete record of a thread's history.
- In-Reply-To:
  - Records the message-ID of the direct parent email.
  - Commonly used by clients to build thread trees.
  - If missing from the References, clients may add it.
- Why It Matters:
  - These fields allow forensic analysts to reconstruct email threads.
  - Help identify related or missing emails.
  - Support deduplication and streamline message review in investigations.

## Host-based email

- What is a Host-Based Email Store?
  - It's any email archive stored locally on a user's device (e.g., .OST or .PST files).
  - These archives are independent of a mail server.
  - Typically consist of:
    - An index file (stores metadata: read/unread, flags, etc.).
    - A message store file (contains the actual message content).
- How to Locate Email Archives:
  - Often found by inspecting installed email clients.
  - File extension searches and Windows registry checks can help locate archives.
  - Many forensic tools automatically detect known archive types.
## Microsoft Outlook

- Outlook uses three main file types to store user data, each with a unique forensic utility:
  - .OST (Offline Outlook Data File): Used for Microsoft 365, Exchange, IMAP, and Outlook.com. It allows offline access and synchronizes with the server.
  - .PST (Outlook Data File): Stores POP email data, archives, and old account configurations. This is the most common archive for user-exported or backed-up email.
  - .NST (Outlook Group Storage File): Introduced with Microsoft 365, these store group conversations and calendars for M365 Groups (not accessible offline).
- File Locations & Recovery
  - Outlook files are typically found in:
    - `%UserProfile%\Documents\Outlook`
    - `%UserProfile%\AppData\Local\Microsoft\Outlook`
  - Outlook also stores search-related keys in:
    - `NTUSER\Software\Microsoft\Office\16.0\Outlook\Search`
- Cached Exchange Mode and OST Files
  - Cached Exchange Mode in Outlook enables offline email access by syncing a copy of the mailbox to an .OST file.
  - Common in Exchange, M365, and Outlook.com environments, OST files let users access emails, drafts, calendar items, etc., even when disconnected.
  - OST ≠ PST: OST files are encrypted and compressed. They cannot be opened natively like PST files.
  - To analyze .OST files:
    - Convert them to .PST format using tools like ost2pst.exe.
    - Use forensic tools (many support .OST natively).
  - OST files are caches, not full backups — they usually store the last 12 months of Exchange data.
  - If Outlook can’t sync due to corruption or connection loss, the orphaned OST might hold data not on the server anymore.
- Parsing and reviewing Outlook database files
  - Tools and Software Support
    - Widespread adoption of .PST led to:
      - Increased support in eDiscovery tools.
      - Compatibility with forensic suites like AXIOM, X-Ways, FTK, EnCase.
    - These tools enable parsing email content, timestamps, attachments, and metadata.
  - Lightweight PST Review Options
    - XstReader: Open-source tool for .PST/.OST/.NST files, written in .NET/C#.
    - XstExporter: CLI version of XstReader, for bulk extraction of messages/attachments.
    - Kernel Data Recovery: GUI tool for preview/export, but exporting often needs a paid version.
- Outlook recovery attachment
  - Secure Temp Folder in Outlook
    - When: Attachments are previewed or opened in Outlook.
    - Where: Stored in a temporary folder located in:
      - `C:\Users\<username>\AppData\Local\Microsoft\Windows\INetCache\Content.Outlook\<RandomFolder>`
    - Registry Location:
      - `NTUSER\Software\Microsoft\Office\<version>\Outlook\Security`
        - (Value: OutlookSecureTempFolder)
  - Problem: Attachments themselves lack timestamps.
  - Solution: Use MFT $FileName timestamps to infer when the attachment was accessed.
  - Advanced Recovery: Files can still be found in:
    - $Logfile
    - USNJournal
    - $MFT from Volume Shadow Copies
  - Investigator Use: Can reconstruct access history and attachment recovery even if Outlook has deleted the files.
## Non-Outlook email clients

- Diverse Email Clients
  - Common clients include: Thunderbird, Windows Mail, eM Client, Mailbird, Inky, The Bat!
  - Each has different storage formats and behaviors.
  - Challenge: You can't prepare for every client in advance.
- Identification Tactics
  - Check:
    - Installed programs
    - Prefetch files (to find program usage)
    - Registry entries (for uninstalled apps)
  - Internet research is often required to understand unknown formats.
- Email Archives
  - Most store messages in clear-text formats (vs. obfuscated Outlook formats).
  - Examples:
    - Thunderbird: Saves emails as .EML; uses .PST for archives.
    - Outlook: Single messages = .MSG, bulk archives = .PST, .OST.
  - Unallocated space may still contain recoverable remnants.
- More Than Just Messages
  - Clients often store:
    - Appointments
    - Task lists
    - Address books
  - These can be exported into formats and recovered like email messages.
## Server-based email

- Server vs. Workstation Storage
  - All email originates from a server, but may later reside:
    - On the server (e.g., cloud-based, Exchange).
    - On a workstation (archived or synced copies).
  - Investigators often face:
    - Mixed environments (e.g., MS365 for live mail + local PST for archives).
    - The challenge of locating all instances of email data.
- Local Workstation Archives
  - Common in environments where:
    - Offline access is important.
    - Retention policies are strict on servers.
  - IT often controls server-side retention, making workstation data vital.
- Modern Server Hosting Trends
  - Traditional on-premises servers have been replaced by:
    - Cloud/SaaS platforms: Microsoft 365, Google Workspace.
  - Challenges:
    - Lack of physical server access.
    - Restricted tool access due to shared cloud environments.
  - Goal remains: Find relevant emails and related logs quickly.
- Deleted Email Recovery
  - Servers may retain deleted emails based on retention policies:
    - Time-based or hierarchical.
    - Some items may be unrecoverable after expiry.
  - Tools like eDiscovery can:
    - Place holds on mailbox deletion.
    - Capture deleted items via versioning mechanisms.
## Email servers Acquisition

- Three Primary Evidence Acquisition Techniques
  1. Export of Individual Mailboxes
    - Traditional method: export from mail server for users of interest.
  2. Use of Specialized Applications
    - Vendor tools (e.g., from Microsoft, Google) to:
      - Search and filter messages.
      - Export targeted data for forensic review.
  3. Use of APIs (Application Programming Interfaces)
    - Automates access to:
      - Mail content (messages, attachments).
      - Server logs and user activity records.
    - Examples: Microsoft Graph API, Exchange Web Services (EWS) API, Gmail History API.
- Operational Insights
  - Preparation is key:
    - Understand the systems in your organization.
    - Collaborate with mail administrators (they often have built-in solutions).
  - APIs may offer deeper access:
    - Can bypass GUI limitations.
    - Allow granular access controls and alternative output formats (e.g., MIME for DKIM validation).
    - Native Microsoft 365 tools typically export in .PST; MIME requires EWS API
## Exchange mailbox extraction

- Mailbox Extraction from Exchange via PowerShell
- Key Features:
1. Basic Mailbox Export
  - New-MailboxExportRequest -Mailbox buckybarnes -FilePath \\Server\Folder\`barnes.pst`
  - Exports the mailbox to a .pst file.
  - Advanced Filtering
    - New-MailboxExportRequest -Mailbox buckybarnes -ContentFilter {(body -like "*HYDRA*") -and (Received -lt "03/02/2012")} -FilePath \\Server\Folder\`Barnes_Filtered.pst`
- Filters based on:
  - Email body content
  - Date ranges
  - Metadata like subject, sender, recipient, folders, etc.
- Automatically Includes Recoverable Items
  - Items from the Recoverable Items folder (deleted items not purged) are also exported.
- Requirements:
  - Must run from an on-premises Exchange Server with Exchange Management Shell enabled.
  - Available from Exchange 2010 SP1 onward.
  - Re`lies on New-MailboxExportRequest (export) and New-MailboxImportRequest (import) cmdlets.
## Microsoft Exchange "Recoverable Items"

- Purpose of the Recoverable Items Folder
  - Replaces the "dumpster" feature from older Exchange versions.
  - Designed for discovery efforts and data retention, particularly during litigation or investigations.
- Retention & Structure
  - Soft Delete: Moved to Deletions subfolder, retained for 14 days by default.
  - Hard Delete: Moved to Purges subfolder, after which the item is unrecoverable.
  - Deleted mailboxes and items are indexed for search and retained for 30 days by default.
- Advanced Features in Exchange & Microsoft 365
  - DiscoveryHold: Prevents purging of items under legal hold.
  - Versions Folder: Stores “copy-on-write” snapshots of altered messages.
  - Auditing:
    - Mailbox/Calendar audit (manual enablement on-premises, enabled by default in Microsoft 365)
    - Logs changes, deletions, access events
  - Message Tracing:
    - Logs detailed metadata (message-ID, sender, IP address, dates, size, etc.)
    - Microsoft 365: On by default, stores 90 days of data; longer retrieval times for data >7 days
## Compliance Search

- Purpose
  - Tracks down suspicious or malicious emails.
  - Supports internal investigations, legal holds, or pre-breach detection.
- Command Syntax (on-prem Exchange example)
  - New-ComplianceSearch –name "Legal Case 81280" –ExchangeLocation "Sales" –ContentMatchQuery '"Widget" AND "Johnson"
- Granular search: All mail components are searchable—even across large datasets.
- No hard limit on mailbox count in M365 (on-premises had a limit of 500 mailboxes/50 GB results).
- Deduplication: Ensures results aren’t bloated by duplicate content.
- Exportable Results: Can export matched emails to PST or use results to trigger litigation holds.

  - Ideal for first-step investigations, helping identify relevant communications.
- Searchable Content Includes:

  - Teams chats

  - Estimate, preview, and export results.

## Exporting Microsoft 365

- Microsoft 365 Mailbox Export via Content Search
  - Tool Used: Microsoft Purview (formerly Security & Compliance Center)
  - Format: Export is in .PST format (emails, calendar entries, etc.)
  - Where: Done after executing a Content Search

## Unified Audit Logging

- Unified Audit Log (UAL) centralizes logging for Exchange, SharePoint, OneDrive, Azure AD, and more.
- Mail auditing is now enabled by default (since 2019), but must be explicitly configured via PowerShell:
  - Set-AdminAuditLogConfig
- Default retention:
  - 90 days (standard)
  - Up to 1 year (Microsoft 365 E5)
  - Up to 180 days (Azure AD logs)
  - Extended with: Set-Mailbox and auditlogagelimilt
- Logging Actions & Categories
  - Actions vary by user type (e.g., Admins have more logged by default).
  - A key log: MailItemsAccessed (tracks what messages a user read).
    - Now available for all tenants (formerly E5-exclusive).
  - Organizations must manually stay updated, or risk missing new audit items added by Microsoft.
  - Logs record client IPs and access device details, aiding in threat detection.
- Searching the Unified Audit Log
  - Use PowerShell to query:
    - Search-UnifiedAuditLog -StartDate 09/01/2023 -EndDate 10/01/2023 -UserIds <user1,user2> -Operations MailItemsAccessed
  - Log availability:
    - SharePoint/OneDrive logs: ~15 minutes after event
  - Exchange/Azure AD: 30 mins – 12 hours

3. Gmail API Access
  - Enables scripted data collection, ideal for:

- Google Vault
  - Included in Google Workspace Business & Enterprise, or can be purchased for Basic users.
  - Vault enables:
    - Data retention, deletion policies, and eDiscovery
    - Search, filter, and export of individual emails, user mailboxes, and Google Workspace app data
  - Export Features
    - Formats:
      - PST or MBOX (email content)
      - XML (Google mail server metadata)
      - CSV (email owner metadata, counts)
    - Export includes MD5 hash checksum file for validation
  - Draft Messages in Vault
    - Drafts are archived even if never sent
    - Subject to the same hold and retention rules
    - If a user deletes a draft, it still stays in Vault
    - Version history:
      - Gmail saves multiple versions of drafts as users compose
      - All versions are saved and retrievable in Vault
      - Stored for 30 days after the final version is saved

  - Confidential Mode Messages
    - A relatively new Gmail feature allowing senders to:

      - Set expiration times
      - Revoke access after sending
    - Implemented via a link to hosted content (not the content itself in the email body)
    - Vault Archives All Confidential Messages:
      - Includes full message content, even if the message is revoked
      - Only accessible via Vault, not Gmail API
      - Fully searchable/exportable
      - Can be identified using the label:
        - label:confidentialmode
- Google Workspace Logging
  - Core Features:
    - Enabled by default on all Google Workspace tiers (formerly G Suite)
    - Exportable to CSV via web console or API
    - Logs help track user activity, email flow, app usage, and admin actions
  - Log Types and Key Details:
    - Admin Log
      - Actions by Google Workspace administrators

    - User Log
      - Login activity (web/admin console)
      - Data Included:Account, log-in type, date, IP address
    - Email Log Search
      - Email sent/received metadata

    - OAuth Log
      - App and device authorizations

    - User Reports / App Usage
      - Account activity overview

  - Key Notes for Investigators:
    - Enterprise tier allows extending email log retention beyond 30 days using BigQuery.
    - Logs can be exported to SIEMs or offline tools.
    - Delays (“lag time”) can occur in User and OAuth logs.
    - Enterprise tools include:
      - Security Center: Monitor spoofing, malware, etc.
      - Custom settings search
    - Useful tools for automation:
      - ALFA (Automated Audit Log Forensic Analysis)
      - SANS scripts and best practices by Megan Roddie
- Business Email Compromise (BEC)
  - Scope & Impact
    - BEC has escalated dramatically:
      - FBI reported $50 billion in losses globally (2022), up from $12 billion in 2018.
    - Cloud email systems (like M365 and Google Workspace) are prime targets.
    - Many compromises involve lack of Multi-Factor Authentication (MFA):
      - Microsoft reported only 27% MFA usage on admin accounts (as of Sep 2022).
      - Google also shows low MFA enforcement.
  - Essential Questions During BEC Investigations
    - What accounts were compromised?
    - Did attackers gain admin or super-admin rights?
    - What data was accessed or stolen?
    - These answers rely almost entirely on log analysis.
  - Log Access Tools & Tips
    - Microsoft 365:
      - PowerShell (e.g., Search-UnifiedAuditLog)
      - Defender for Cloud Apps
    - Google Workspace:
      - Admin Alerts (System Defined Alerts, often disabled by default)
    - Not all features are enabled by default—verify logging before an incident occurs.
## Webmail Forensics

- Where is the Email Stored?
  - Typically stored on provider servers (cloud-based).
  - Exception: Users using POP or IMAP may have local copies in email clients.
- What Investigators Should Do:
  - Look for webmail domains (e.g., gmail.com, yahoo.com).
  - Request IP address logs and subscriber information from the provider (often via legal process).
  - Search browser history and auto-complete databases on the target machine.
- Cached Content & Recovery:
  - Dynamic web content (JavaScript-heavy interfaces) reduces chances of cached page recovery.
  - But stream carving and keyword searching from memory/disk can help recover fragments.
  - Cached pages, search forms, or attachments may be partially available even without full credentials.
- Legal Caution:
  - Accessing webmail without proper authorization can violate civil/criminal laws.
  - Investigators must seek court orders for email data from providers or avoid unauthorized access.
- Webmail collection
  - Email Collection from Cloud Providers & Webmail (e.g., Gmail, Outlook.com)
  - Google Takeout
    - Allows users to export all data: Gmail, Drive, Contacts, Calendar, Photos, etc.
    - Requires authentication and produces ZIP archive with data in MBOX format.
    - Adds X-Gmail-Labels to help identify folder usage (read/unread, etc.).
  - IMAP Synchronization
    - Common for collecting from any email service that supports IMAP (e.g., Outlook.com, Yahoo Mail, AOL).
    - Forensic workstations can sync email to pull local copies.
    - IMAP avoids Outlook’s modifications to headers, allowing better DKIM/ARC validation.
  - Magnet AXIOM
    - Collects from cloud sources: Microsoft 365, Google Workspace, Gmail, iCloud.
    - Supports collection via admin APIs or IMAP/POP/MBOX protocols.
  - Metaspike Forensic Email Collector (FEC)
    - Specialized forensic tool supporting Exchange Web Services, Graph API, and IMAP.
    - Can extract tokens from logged-in users for access without reauthentication.
    - Supports export of IMAP server logs, helping detect manipulated messages using:
      - Sequence numbers
      - IMAP Internal Date Message Attribute
- Webmail & ISP Legal Guide
  - Legal & Law Enforcement Guides
    - Every major provider (e.g., Google, Yahoo, Facebook) offers internal or public-facing legal request guidelines.
    - These guides explain:
      - What data is retained (email headers, subscriber info, IP addresses, etc.)
      - Retention duration and purge policies
      - How to legally request access (often requiring a court order)
  - Investigative Value
    - IP address logs may show:
      - The machine that created the account
      - Sessions from subsequent accesses (potentially spanning months)
    - Subscriber metadata helps link accounts to individuals or computers
  - Public Transparency Tools
    - Facebook & Google offer excellent tools like the Google Transparency Report
    - Other archives:
      - Maintained by the National Consortium for Justice Information and Statistics
      - May require verified law enforcement access
- Webmail Artifact
  - Valuable Artifact Types:
    - Subject lines in browser titles (e.g., Gmail) can aid in keyword matching or timeline building.
    - RAM, browser cache, unallocated drive space may contain entire or partial messages.
    - URLs and page titles reveal folder names and accessed content (e.g., inbox, sent, drafts).
    - Browser history provides timestamps, which can be correlated with other events.
    - Search terms typed help infer user intent or actions (e.g., “password reset”).
- Webmail remnants
  - Decline of Webmail in Browser Cache:
    - Dynamic content has reduced the volume of webmail data stored in browser cache.
    - Despite this, string search techniques can still yield useful results.
    - The keyword "mail" is a good starting point when scanning for cached webmail artifacts.
  - Investigative Workflow:
    1. Target webmail domains (e.g., google.com, yahoo.com) in browser cache files.
    2. Filter out zero-byte files.
    3. Export candidate files for manual review.
    - se tools that support JSON and XML formats—many cached files use these structures.
- Webmail RAM and Drive Extraction
  - Why collect RAM images?
    - Webmail content is rarely stored in browser caches due to dynamic content loading.
    - However, email data is often still resident in RAM during a browser session.
    - Memory capture allows for recovery of these ephemeral, non-persistent artifacts.
  - Tools and Techniques:
    - Magnet AXIOM (formerly Internet Evidence Finder):
      - Integrates stream carving tools specifically targeting webmail, social media, and browsing sessions.
      - Example on this slide shows a recovered ProtonMail email from a RAM.raw image.
    - Competitors: Tools like Belkasoft and AccessData also support stream carving for volatile webmail content.
- Mobile Email
  - Why Mobile Email Matters in Forensics
    - Many investigators overlook mobile devices during email investigations.
    - Smartphones often sync with corporate mail servers and may only keep partial or temporary data.
    - Verifying how mobile apps interact with email systems is critical—particularly in cloud environments.
  - Key Acquisition Sources
    1. Mobile Device Management (MDM) Logs
      - Some MDM solutions log call/SMS/MMS metadata.
      - Examples:
        - IBM MaaS360
        - Citrix Endpoint Management
      - Note: Actual message content is rarely logged—only metadata like timestamps or message routing.
    2. Smartphone Backups on Local Machines
      - Backups can provide deleted data or historical snapshots.
  - Backup File Paths
    - Android Devices:
    - Look for .ab (Android Backup) files or vendor backup tools:
      - Samsung Smart Switch
      - LG Bridge
      - Huawei HiSuite
    - iOS Devices (Windows Vista+):
    - Backup files may be located at:
      - `C:\Users\<UserName>\AppData\Roaming\Apple` Computer\MobileSync\Backup
      - `C:\Users\<UserName>\Apple\MobileSync\Backup`
      - iOS backups include plist files with metadata (serial number, IMEI, etc.).
- Forensic Email Intelligence (FEI)
  - Key Features of FEI
    - Comprehensive header parsing for both SMTP and MAPI formats.
      - Extracts hidden metadata.
      - Highlights inconsistencies and anomalies.
    - Timestamp extraction:
      - Gathers and displays all relevant timestamps in one view.
    - Consolidated IP and domain data:
      - Links IPs/domains to reputation, geo-location, and domain intelligence services via APIs.
